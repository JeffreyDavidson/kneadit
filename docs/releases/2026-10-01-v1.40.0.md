# KneadIt v1.40.0

Date: 2026-10-01
Tag: v1.40.0

## Summary

An audit-driven release that makes the settings, dates and checkout rules bakers configure actually apply, closes several money and permission gaps, and fixes the storefront order form's broken API calls. It builds on the v1.39.2 and v1.39.3 hotfixes (delivery tier pricing, online gift card purchases), which are already live.

## Highlights

### Checkout and orders

- **Coupon codes are required on storefront orders.** The storefront no longer accepts a coupon by its numeric id, so private single-use coupons can only be redeemed with their code (#1227).
- **Stripe payments are checked against the order total.** An order is marked paid only when the amount paid equals its total. Otherwise it stays unpaid, the payment intent is stored, and the bakery's owners get a notification. Customers can't edit an order while its card checkout is open. Orders paid partly with a gift card and no discount were previously charged the full price on Stripe, and are now charged the amount due (#1238).
- **Customer order edits are re-priced.** Discounts scale down with the subtotal, never up, and the gift card amount is capped and credited back. An edit that drops the order below the minimum order or the free-delivery minimum is rejected (#1231).
- **Pickup slots are enforced.** When pickup slots are on, the time is required and must be an open slot with room, including inside the order transaction. A partial-day blocked date now limits the slots to its open hours (#1235).
- **Seasonal products** can't be ordered outside their window at checkout, judged by delivery date (#1222).
- **Staff quick orders** are priced by the bakery's delivery tiers (#1220), and the Quick Order page can create orders again. Customer email is now required on the form (#1229).
- **Admin order editing:** status and payment status can't be changed from the edit form, so cancelling, delivering and baking always go through the order actions (inventory, coupon and gift card reversal, loyalty points, emails). A new Mark Paid action records payments taken outside checkout (#1228).
- **Storefront order form:**
  - Availability, the capacity check, "order again", coupon and gift card apply, and order tracking messages all misread the API's `{data: …}` responses. Closed days, capacity warnings and applied discounts now work (#1236).
  - Server validation errors show under their fields (#1239), and domain failures such as minimum order, out of stock and a full date return proper 422 responses instead of a silent reload (#1243).
- **Saved payment methods** are read from the right setting on the storefront (#1204).

### Bakery-local dates and times

Everything that means "today" now follows the bakery's timezone setting instead of UTC:

- engagement emails, birthdays and repeat-order reminders (#1206)
- dashboard widgets and stats, analytics, seasonal availability and the Quick Order date picker (#1210, #1213)
- admin page and form defaults, the order and social calendars, shopping lists (#1226)
- stats, storefront trend and the birthday widget cache (#1234)
- report and widget date ranges, which now cut at the bakery's midnight (#1242)
- the remaining admin pages (#1240)

Scheduled customer and baker emails (birthdays, repeat reminders, weekly digest, low-stock alerts) now go out at the bakery's local send time: the scheduler runs them hourly and each bakery is processed at its own hour (#1217). `BakeryClock` now reads the current bakery's settings on every call, so one scheduled run covering several bakeries uses each one's own timezone (#1232).

### Loyalty, rewards and coupons

- Loyalty dashboard activity shows the right color and sign for each point type (#1205). Outstanding points and the storefront history account for redemptions and adjustments (#1215). Top customers include adjustments, and recent awards show only earned points (#1223).
- The reward and coupon forms now require the amount or percentage they need, and free-product rewards can pick a product (#1224).
- Repeat-order reminders send again (#1214).

### Settings

- The Settings page validates on the server, and fields that were silently dropped are saved (#1221). Numeric fields have limits, new tenants open with their default payment method and other list defaults selected, and Send Test Webhook validates first (#1237).
- New sections and fields: birthday, review, catering, store address and label settings (#1212), and a **Loyalty Program** section for the program name, earn rate, tiers, multipliers and free delivery (#1233).

### Other

- Blog post management is limited to manager roles and above (#1216).
- Homepage builder supports hero images, hero styles and page hero uploads (#1218).
- Forge calls retry only transient failures and log rejected requests (#1219).
- The reorder reminders page, admin logo and 404 page read the bakery name correctly, and a new test guards against missing settings properties (#1240).
- `AppServiceProvider` no longer registers the bindings and rate limiters that the dedicated providers already register (#1230).
- More test coverage (#1208, #1209, #1211) and a browser test for storefront delivery orders (#1225).

## API change

- `POST /api/v1/orders`: when pickup slots are enabled, pickup orders must send a `delivery_time` that is an open slot (#1235).
- The storefront order form posts `coupon_code` instead of `coupon_id`. The public API already used `coupon_code`.

## Database and deployment notes

- **Tenant migration:** `2026_09_30_201500_add_original_pricing_to_orders_table` adds nullable `original_subtotal` and `original_discount_amount` to `orders`. Run tenant migrations after verifying tenant backups. Older orders fill these in on their first customer edit.
- **Scheduler:** the four tenant-facing email commands now run hourly and decide per bakery whether it is send time. The existing scheduler entry (`schedule:run` every minute) needs no change. Once bakeries set their timezone, their sends move to the local hour.
- **Config:** `kneadit.delivery_fees` is removed. Nothing reads it any more, since delivery is priced from each bakery's delivery fee tiers.
- **Behavior changes bakers may notice:**
  - Order edits by customers re-price discounts and can be rejected below a minimum.
  - Customers can't edit an order while their card payment is open.
  - The admin order edit form no longer changes status or payment status. Use the action buttons.
  - The Quick Order form requires a customer email.
  - Saving the Settings page now fails with a clear message on invalid values.
- **Tell bakers to set their timezone** in Settings → Order Settings. It defaults to UTC, so nothing changes until they do.
- **Check Stripe after deploying:** card payments for orders paid partly with a gift card and no discount, made before this release, were charged the full price. Refund the difference where it applies.
- Follow the standard deployment checklist in [Operations](../operations.md#deployment-and-release), including `bin/sync-version` before configuration caching.

# KneadIt v1.48.1

Date: 2026-10-05
Tag: v1.48.1

## Summary

Bakery subdomains work in production again. Every `{bakery}.getkneadit.app` address, storefront and admin, returned "not found"; bakeries could only be reached on a verified custom domain.

## Highlights

- **Bakery subdomains** (#1324). Bakeries are identified on `{id}.{tenant domain}` (for example `bakery-on-biscotto.getkneadit.app`) even though the tenant domain isn't one of the app's central domains. The tenancy package only recognised a subdomain under a central domain, so in production every subdomain was looked up as a custom domain and failed. Local and test setups used a tenant domain that is also a central domain, which is why it only happened in production.
  - Custom domains are unchanged. A `domains` row holding the full host still wins.
  - Unknown subdomains, nested hosts (`a.b.getkneadit.app`), the bare tenant domain and unrelated hosts still return "not found".
  - This matters for every new bakery: until a custom domain is verified, its storefront and admin links use the subdomain.

## Database and deployment notes

- No database migrations and no configuration changes.
- Follow the standard deployment checklist in [Operations](../operations.md#deployment-and-release), including `bin/sync-version` before configuration caching.
- After deploying, check that a bakery subdomain's storefront, `/menu` and `/admin/login` load, that an unknown subdomain still returns 404, and that the custom domain still works.

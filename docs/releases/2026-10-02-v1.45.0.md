# KneadIt v1.45.0

Date: 2026-10-02
Tag: v1.45.0

## Summary

Customers on a product's waitlist are now emailed automatically when the product comes back, and the browser smoke test that checks order messages is more reliable.

## Highlights

- **Waitlist notifications are automatic.** The storefront tells customers "You'll be notified when this item is available!", but until now nothing sent that email unless staff remembered to click **Notify Waitlist** after reactivating a product. When a product changes from inactive to active, its waitlist is now emailed automatically. The email is queued after the save, so saving a product never waits on email, and it respects the bakery's "product available" email setting. Each customer is emailed once (#1276).
  - **Notify Waitlist** stays as a manual resend. It is hidden for inactive products, and it never sends for a product that isn't available, so customers can't be told "it's back" when it isn't. Its confirmation text now says "Each customer will be emailed once and marked as notified."
  - Joining the waitlist for a product that is already available is declined with "This item is available now."
- **Browser test reliability.** The browser smoke test that sends a message from the order tracking page now waits for the messages to finish loading before typing, and failed browser smoke runs upload their screenshots so failures can be diagnosed (#1275).

## Database and deployment notes

- No database migrations.
- **Reactivating products in bulk:** changes made with a bulk database update don't fire the automatic notification. Use **Notify Waitlist** for those.
- **Make sure tenant migrations run on deploy.** The Forge deploy script runs only the central migrations, so add `php artisan tenants:migrate --force` after `php artisan migrate --force` (this release has none, but later ones will).
- Follow the standard deployment checklist in [Operations](../operations.md#deployment-and-release), including `bin/sync-version` before configuration caching.

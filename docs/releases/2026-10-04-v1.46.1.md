# KneadIt v1.46.1

Date: 2026-10-04
Tag: v1.46.1

## Summary

A bakery's custom domain can now be verified when it is served through a proxy such as Cloudflare.

## Highlights

- **Custom domains behind a proxy are verified** (#1292). A domain counts in links and emails only once it is verified, and verification required the domain's DNS to point straight at the server. A domain that uses Cloudflare's proxy resolves to Cloudflare's addresses instead, so it could never be verified even though its site worked. Verification now also passes when the domain answers over HTTPS with an ownership proof that only this application can produce for that exact host.
  - The proof is a keyed hash of the host, served at `/.well-known/kneadit-domain-proof` on each custom domain. It is never cached, it is not served on the platform's own domains, and it still answers when a bakery's storefront is paused. A proof for one domain never verifies another.
  - A domain that points straight at the server keeps its existing check, and now also needs this proof.
  - The Settings → Custom Domain page shows "DNS: served through a proxy (Cloudflare)" for a proxied domain.

## Database and deployment notes

- No database migrations.
- After deploying, a domain verifies on the next daily `tenants:verify-custom-domains` run, or right away with **Verify domain** on the bakery's Settings page (platform admins have the same action on the bakery's Edit page). Production's one bakery, `bakery-on-biscotto`, uses `bakeryonbiscotto.com` through Cloudflare's proxy, so expect its links and emails to switch to the custom domain after that check.
- The deploy script now runs `php artisan tenants:migrate --force` after `php artisan migrate --force`. This release has no migrations, so it is a chance to confirm that step runs cleanly.
- Follow the standard deployment checklist in [Operations](../operations.md#deployment-and-release), including `bin/sync-version` before configuration caching.

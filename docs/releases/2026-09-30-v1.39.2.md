# KneadIt v1.39.2

Date: 2026-09-30
Tag: v1.39.2

## Summary

Hotfix: storefront delivery orders were impossible to place.

## Fixes

- **Delivery orders failed validation.** The checkout submits `delivery_tier` as the position of the bakery's configured Delivery Fee Tier (`"0"`, `"1"`, …), but the storefront and API order requests only accepted fixed names (`under5`, `5to10`, `10to15`, `over15`). Every storefront delivery order failed with "The selected delivery tier is invalid." Both requests now accept the bakery's configured tier positions.
- **Delivery was priced from global config.** `CalculateOrderTotals` used `config('kneadit.delivery_fees')` instead of the bakery's tiers and ignored the free-delivery minimum, so the server-side fee couldn't match what checkout showed. It now uses the bakery's tier fee and makes delivery free at or over the free-delivery minimum, matching the checkout's own calculation.
- **Delivery could be ordered while turned off.** Both order requests now reject `delivery_type=delivery` when the bakery has delivery turned off.

## API change

`POST /api/v1/orders` (`StoreApiOrderRequest`) now takes `delivery_tier` as the tier position, like the storefront. Clients sending `under5`/`5to10`/`10to15`/`over15` must switch.

## Database and deployment notes

- No database migrations.
- Staff quick orders (`CreateQuickOrder`) still use the global `kneadit.delivery_fees` config; a follow-up will move them to the bakery's tiers.
- Follow the standard deployment checklist in [Operations](../operations.md#deployment-and-release), including `bin/sync-version` before configuration caching.

# KneadIt v1.44.0

Date: 2026-10-02
Tag: v1.44.0

## Summary

Two production fixes found while deploying v1.43.0: PayPal invoice payments are checked again, and a custom domain counts as verified only when it actually serves over HTTPS.

## Highlights

- **PayPal invoice payments are checked again.** The hourly `paypal:check-payments` job had failed every hour since 2026-09-27 with `no such table: settings`, so no PayPal invoice was ever polled. Paid invoices never marked their orders paid, and cancelled or refunded invoices never updated. The job now sets up its PayPal connection per bakery, after that bakery is selected, using each bakery's own credentials. Orders marked paid also resolve per bakery. A new test runs every scheduled per-bakery command with no bakery selected and fails if any touches a bakery-only table (#1273).
- **Custom domains are verified over HTTPS, not just DNS.** A domain counts as verified only if DNS points at the server and `https://<domain>/up` answers with a valid certificate. Before, a domain with correct DNS but no certificate was marked verified, and email links to it opened nothing. The bakery's Custom Domain settings page and the platform admin's bakery page now show the DNS and HTTPS parts separately, offer **Verify domain**, and offer **Request SSL certificate** when only HTTPS is missing (#1272).

## Database and deployment notes

- No database migrations.
- **Make sure tenant migrations run on deploy.** When v1.43.0 deployed, Forge ran the central migrations but not `tenants:migrate`, so the bakery database was missing five migrations until they were run by hand. Add `php artisan tenants:migrate --force` to the Forge deploy script, after `php artisan migrate --force`.
- **PayPal catch-up.** Because the check failed for days, orders paid by PayPal invoice since 2026-09-27 are still unpaid. The first hourly run after this deploys checks every unpaid order that has a PayPal invoice and marks the paid ones. Bakeries should still check recent PayPal-invoiced orders, and **Mark Paid** is available for any that don't update.
- **Custom domains may become unverified.** On the next daily run (05:30 UTC), any bakery whose custom domain has no valid HTTPS certificate becomes unverified, and its email links use the bakery's subdomain until the certificate is issued. Issue it in Forge, or use **Request SSL certificate** on the settings page or the platform admin's bakery page. To re-check right away:
  ```bash
  php artisan tenants:verify-custom-domains
  ```
- Follow the standard deployment checklist in [Operations](../operations.md#deployment-and-release), including `bin/sync-version` before configuration caching.

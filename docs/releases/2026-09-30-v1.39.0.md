# KneadIt v1.39.0

Date: 2026-09-30
Tag: v1.39.0

## Summary

Make every ordering limit bakers can set in admin actually apply: capacity limits, holiday limits and deadlines, Schedule Manager limits and cutoffs, and lead time. Add a bakery timezone so all of it follows the bakery's local day. Checkout, the order API and the storefront availability calendar now share one set of capacity rules.

## Highlights

- **Capacity limits:** Weekday limits are saved by name and recur every week, a second weekday limit no longer crashes, duplicates are rejected, and "Block Day Entirely" closes the day. Legacy weekday numbers import with 0 = Sunday (#1191, #1192).
- **One capacity rule set:** Order limits come from the most specific source: a date capacity limit, then an active holiday, then a weekday capacity limit, then Schedule Manager, then the tenant default. Schedule Manager and holiday max orders are now enforced (#1193).
- **Holiday order deadlines:** Customers can't order for a holiday after its order deadline. The deadline day itself stays open (#1194).
- **Availability calendar:** The storefront calendar uses the same rules as checkout, via the new `DateCapacityRules`, and drops from about 120 queries to 5 per request (#1195).
- **Order cutoff, lead time and timezone:** A new bakery timezone setting (default UTC). Schedule Manager's order cutoff is enforced: after the cutoff, an order counts as placed the next day. The admin "Minimum Order Lead Hours" setting is now actually read. The order page, date picker and order requests share one earliest-delivery-date rule (#1196).
- **Bakery-local dates:** Holiday deadlines, the calendar, the capacity dashboard widget, upcoming holidays and holiday deadline badges use the bakery's local date. "Deadline passed" no longer shows on the deadline day itself (#1197).
- **Tooling and tests:** Composer scripts no longer hit the 300-second process timeout; pre-push checks skip delete-only pushes; a redundant catering quote observer is removed; test fixes for dotted checkout paths and no-op imports (#1185–#1190).

## Database and deployment notes

- **Tenant migration:** `2026_09_30_013148_drop_date_from_capacity_limits_table` drops `capacity_limits.date` and its unique index. Run tenant migrations. The column isn't read any more. It can't be restored from the migration, so verify tenant backups first.
- **Behavior changes bakers may notice:**
  - Tenants who saved the settings page now get the lead time they saved. The form default was 48 hours, where 24 was actually enforced.
  - Capacity limits set to 0 now defer to the holiday, Schedule Manager or default limit.
  - Schedule Manager and holiday max orders and order cutoffs now limit checkout.
  - Blocked capacity limits close the day.
- **Timezone:** Defaults to UTC, so nothing changes until a baker picks their timezone in Settings → Order Settings. Tell bakers to set it.
- **Old weekday limits:** Rows saved before #1192 have `day_of_week = '0'` and show "—" until a baker re-saves them. By decision, there's no data migration.
- Follow the standard deployment checklist in [Operations](../operations.md#deployment-and-release), including synchronizing the version before configuration caching.
